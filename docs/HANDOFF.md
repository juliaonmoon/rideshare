## Rules

- **Settings (2026-10-19, migration 009):** new Settings tab with separate Driver and Rider sections (defaults for new trips/requests, seats, auto-accept with seat cap, ride style tags). DB: `user_settings`, `ride_styles()`, and an after-insert trigger on `matches` for auto-accept. Run `supabase/migrations/009_settings.sql` once. Benchmark notes: docs/BENCHMARK.md.
- **Pickup limits (2026-10-19, migration 011):** drivers choose how many riders they pick up (1-4), the most extra minutes for ONE pickup (max_detour) and for ALL pickups together (max_total_detour). Matching checks all three (matching.js); respond_match enforces the pickup count in the database; auto-accept only takes the first rider of a date. Matching times are still straight-line estimates: replacing them with Google traffic-aware times is the next step (see chat/plan).
- **Google drive times (2026-10-19):** matching now uses Google Routes API times between all 19 neighbourhood centres, in four time-of-day tables (weekday morning / midday / afternoon, and weekends+evenings), stored in prototype/traffic.js (1,444 lookups, fetched once from the live site with the existing restricted key). Falls back to the old straight-line estimate for any place not in the table. Pricing still uses the old distance estimate on purpose (the database caps points with the same estimate). Refresh = re-run the computeRouteMatrix request and paste new numbers. Next: exact addresses would need live lookups per match.
- **Driver alerts + driving mode (2026-10-22, migration 012, new APK):** Start my trip now always starts the Android background helper ("driving mode"), even with no accepted rider yet. The helper polls `driver_alerts_token` every 15 s: it sends the position only while a ride is in progress, shows a high-priority phone notification "<name> asked for a seat" for each NEW request (requests already waiting at start are not announced), and switches itself off after ~1 min of nothing on today or when the token expires. If the database has no 012 yet, it falls back to the old position-only behaviour. Tested on the emulator against a fake server and in the local Postgres harness. Accepting a rider mid-drive: open the alert, accept, tap Start my trip again to refresh the Google Maps stops. Next: real push notifications (FCM) so alerts also work when the app was never started.
